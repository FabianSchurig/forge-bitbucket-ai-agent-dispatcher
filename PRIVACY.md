## 2. Overview

AI Agent Dispatcher is an Atlassian Forge application that listens for
trigger keywords in Bitbucket Cloud Pull Request comments and dispatches a
CI/CD pipeline build. The app runs entirely on the Atlassian Forge serverless
platform within the customer's own Atlassian Cloud tenant.

**The app does not operate its own servers or databases.** All processing
occurs within Atlassian's Forge infrastructure, governed by
[Atlassian's own privacy policy](https://www.atlassian.com/legal/privacy-policy).

---

## 3. Data Processed

The app processes the following data exclusively within the Atlassian Forge
runtime environment:

| Data | Purpose | Source |
|------|---------|--------|
| Pull Request comment text | Detect trigger keyword and forward to CI pipeline | Bitbucket PR comment event |
| Comment author (Atlassian account ID) | Forward to CI pipeline for attribution | Bitbucket PR comment event |
| Repository and workspace identifiers (slugs, UUIDs) | Route the pipeline dispatch to the correct repository | Bitbucket PR comment event |
| PR source branch name | Forward to CI pipeline so it can check out the correct code | Bitbucket Pull Request API |
| Admin-configured settings (trigger keyword, CI provider config, pipeline variables) | Persist workspace/project configuration | Forge Storage API (encrypted at rest) |
| Monitoring event records (timestamp, project/workspace/repo UUIDs, PR ID, comment ID, dispatch status/provider/message, optional build URL) | Show recent dispatch outcomes in the settings UI when monitoring is enabled | Generated by app runtime and stored in Forge KVS |
| Jenkins API token (only when Jenkins provider is used) | Authenticate requests to the customer-configured Jenkins API | Set by admin via Forge Encrypted Storage (`kvs.setSecret`) |

### Data NOT collected

- No personal data is collected outside of standard Bitbucket identifiers and
  the PR comment content that users submit themselves.
- No email addresses, IP addresses, browser fingerprints, or tracking cookies.
- No analytics, telemetry, or usage tracking of any kind.
- No data is transmitted to third-party services operated by the app
  publisher. When Jenkins is configured as CI provider, requests are sent
  only to the customer-specified Jenkins instance.

## 4. Legal Basis for Processing (Art. 6 GDPR)

| Processing activity | Legal basis |
|---------------------|-------------|
| Reading PR comment content and author to dispatch a build | Art. 6(1)(f) GDPR – Legitimate interest of the workspace administrator who installed and configured the app to automate CI/CD workflows |
| Storing admin-configured settings in Forge Storage | Art. 6(1)(f) GDPR – Legitimate interest in providing persistent configuration for the app's functionality |

The legitimate interest is the automation of CI/CD pipeline dispatch as
explicitly configured by the workspace or project administrator. No data
is processed beyond what is strictly necessary for this purpose (data
minimisation, Art. 5(1)(c) GDPR).

---

## 5. Data Storage and Retention

- **Configuration data** (trigger keyword, CI provider settings, pipeline
  variables) is stored in Atlassian Forge Storage (encrypted at rest) and
  persists until the administrator changes or deletes it, or until the app
  is uninstalled.
- **Monitoring events** (when enabled by the admin) are stored in Forge
  Storage as a bounded per-project list of the 50 most recent events.
  Older events are automatically trimmed and deleted on a best-effort basis.
- **Transient event data** (PR comment text, branch name, etc.) is processed
  in memory during pipeline dispatch and is not persisted by the app. It is
  forwarded to the configured CI system as build parameters.

Upon uninstallation of the app, all Forge Storage data associated with the
installation is deleted by the Atlassian platform.

## 9. Security Measures

- The app runs in Atlassian's Forge sandboxed serverless environment with
  no direct access to the underlying infrastructure.
- Secured pipeline variables are stored encrypted in Forge Storage and
  masked in CI/CD logs by Bitbucket.
- API authentication uses Forge's built-in app identity (`asApp()`) — no
  credentials are stored in source code.
- The app follows the principle of least privilege: only the minimum
  required Bitbucket permission scopes are requested.

## Zusammenfassung (German Summary)

Diese App verarbeitet ausschließlich Daten, die bereits in Ihrem
Atlassian-Cloud-Tenant vorhanden sind (Pull-Request-Kommentare,
Repository-Informationen), um CI/CD-Pipelines auszulösen. Es werden
keine personenbezogenen Daten an den App-Herausgeber oder sonstige Dritte
übermittelt. Die gesamte Verarbeitung findet innerhalb der Atlassian-Forge-
Infrastruktur statt. Konfigurationsdaten werden verschlüsselt in Forge
Storage gespeichert und bei Deinstallation der App gelöscht.
